# 秘书层动态扩展机制（Secretary Scale）· 设计文档

> Issue #100 决策① · 承载：`local-agent/scale/` 扩展（secretary_scale + secretary_ability）。
> 秘书层不写死层数，靠**识别/注册/路由三层 + 权限边界护栏**动态增减；秘书只交接不执行。

## 一、问题（用户盲区指认）

用户（Issue #100 ①）：

- **不给他写死定级**，而是让他基于实际情况能被扩展：秘书机制应基于**信息流位置 +
  任务是否相对独立**，某些场景用得特别多就适合形成秘书机制负责；
- 未来可能发展成**很多个层的服务 + 层间路由**（对齐 LanceDB 那种分层数据库方向：
  分领域 + 横向切片，不是死板 N 层），靠持续扩展实现功能/责任/记忆/工具一致；
- **秘书主要用来交接，不是完成任务**：后面有专门开发，不该把秘书扩展成能完成所有任务；
  **要有一条边界 + 自动化控制和边界的机制**，让秘书在合理范围内有成长效果。

## 二、方案（对齐用户拍板）

秘书层做成**动态扩展机制**，不是静态层表。三层 + 一道护栏：

| 层 | 职责 | 确定性判据/规则 |
|---|---|---|
| **识别层** | 判定"哪段信息流 / 哪个相对独立场景值得设一个秘书" | 复用率 ≥ 阈值 + 独立边界评分 ≥ 阈值 + **不需终端执行**；需终端执行即拦下不设 |
| **注册层** | 秘书以"交接域服务"形式动态挂载/卸载（可增可减） | domain 唯一 + 必填 handoff_to（不许吞活）+ 生命周期 registered→active→draining→unregistered |
| **路由层** | 层间路由：请求 → 命中秘书域 → 交接给 handoff_to；未命中回终端开发线 | 命中即交接（秘书只交接到下游，不执行）；不吞活不改形 |
| **权限边界护栏** | 秘书只交接不执行；越权接终端任务即拦截 | HANDOFF_DUTY 放行 / TERMINAL_DUTY 拦截 / 未知宁拦不放 |

### 秘书 = "可交接的边界域服务"
每个秘书服务 = `{domain, desc, handoff_to, reuse, status}`：
- **domain**：该秘书负责的交接域（如 mcp-server / 端口管理 / 服务启动）；
- **handoff_to**：命中后交接给的下游终端角色/线（秘书只交接到此，不执行）；
- **reuse**：复用率信号，被命中一次累计一次，供识别层评估成长。

### 识别层判据（确定性，不靠感觉）
三维：
1. **复用率 reuse_count**：被 ≥ reuse_threshold(3) 个独立请求/场景高频复用；
2. **独立边界评分**：clear_interface(0.4) + single_owner(0.3) + self_contained(0.3)
   加权 ≥ boundary_threshold(0.6)；
3. **不需终端执行**：该场景若需写业务代码/跑业务（requires_execution=True），
   走开发线而不设秘书（秘书只交接不执行）。

三维都满足 → warrant=True（建议增设该秘书）；任一不满足 → 暂不增设。

### 权限边界护栏（不靠自觉 · 已接入路由强制点）
`guard(duty)`：交接/路由/分诊（HANDOFF_DUTY）→ 放行；实现/开发/改bug/执行/交付结果
（TERMINAL_DUTY）→ 拦截；未知职责 → 宁拦不放（防越权成长）。秘书只做**引导、交接、
路由、调度**，不承担终端落地结果——那是专门开发线的职责。

**运行时强制（不靠调用方自觉）**：`route_request(request, duty=...)` 在路由入口
先调 `guard(duty)` 校验——若请求声明终端执行类职责（implement/develop/fix_bug/
execute/write_code/deliver_result 等），护栏即确定性拦截、返回 `blocked: true`，
不回路由到任何秘书域（`route_blocked` 留痕），直接回终端开发线。

## 三、与既有机制关系

| 既有机制 | 关系 |
|---|---|
| scale/plugin（角色插件化） | 秘书服务注册层复用"动态挂载不写死"思路，秘书服务独立于角色类 |
| 架构·秘书 强制入口 | 默认入口秘书仍负责诉求接收路由；本机制让"可设哪些秘书层/服务"可动态增减成长 |
| dispatch / depth 派发 | 秘书路由命中后交接 handoff_to（可衔接 DispatchAbility / awake 真唤醒）|
| dev-standard 确定性检查 | 护栏沿其"确定性检查器"思路，拦截不靠自觉 |
| AGENTS · 默认入口协议 | 秘书不吞活不改形（路由层未命中回终端开发线），防秘书越权接终端任务 |
