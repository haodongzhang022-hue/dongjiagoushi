# 评审→测试 任务转交工具沉淀（HANDOFF_TOOL）

> 触发：Issue #55「评审交任务不会 @架构·测试，没有真交付而是描述；架构·测试要接手继续开发」。

## 定位

本能力是**市场·工具**层沉淀的通用基建：解决协作链路上「下游只描述、不真唤醒」的断裂。
规则层已有「触发强制化（显式 `[触发:角色全称]` 最高优先）」+「七层协作深度（路由真实唤醒）」，
但评审/测试两个角色此前**没有把"转交/接手"落成显式能力**，导致行为停留在描述。

## 能力清单

| 角色 | 能力 | 作用 |
|------|------|------|
| 架构·评审 | `handoff_to_tester()` | 评审通过（disposition=merge/proceed）后，用完整 `@org/repo(架构·测试)` + `[触发:架构·测试]` 投接力卡**真实唤醒**测试，并校验 `awakened` 回执；未通过（fix_bug）则不转交、走 `[回转] 退回:架构·开发`——**须带完整 `@org/repo(架构·开发)` + `[触发:架构·开发]` 全路径出发**（#142 机制加固，缺完整 @ = 假触发） |
| 架构·评审 | `passes_to_tester()` | 判定处置标签是否放行转交（merge/proceed 才放行） |
| 架构·评审 | `revert_to_developer()` | 🔴必修 → 回转开发（不转交测试） |
| 架构·测试 | `take_over_and_develop()` | 收到转交后 **`[接单]` + `ack_wake` 回执 + `start_work` 开工 + `track_progress` 进度尺推进**，真正接手继续开发（不只描述） |

## 防"只描述"的三层强制

1. **条件强制**：评审**必须**给规范处置标签；merge/proceed 才允许转交测试，否则走对应处置。
2. **唤醒强制**：转交用 `awake()` 投递 `@org/repo(架构·测试)` + `[触发:架构·测试]` 接力卡，
   并校验 `awakened` 回执——**未回执即转交未真实成立**，须重触发或升级，不静默放行。
3. **接手强制**：测试收到转交**必须**回执 `[接单]` + 开工 + 进度尺推进，完成"接手→开发→到结果"闭环。

## 测试

`local-agent/tests/test_review_tester_handoff.sh`（5 项信号灯全绿）：
1. 评审通过 merge/proceed 真实转交测试且可校验回执；
2. 评审未通过 fix_bug 不转交、走回转开发；
3. 测试接手三闭环（接单+开工+进度尺）；
4. 测试回执后评审复校验转交成立（awakened=True）；
5. 输出契约含转交/接手能力。

## 复用

BaseRole 已全员挂载派发/深度/@ 定位能力，本能力仅是评审/测试角色的**显式业务封装**，
供全链路评审→测试环节复用；其他岗位转交同理可套用 `awake` 路由真实唤醒模式。
