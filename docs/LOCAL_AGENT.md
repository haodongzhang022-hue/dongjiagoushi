# 本地 Agent 团队 · 架构设计（架构八步产物）

> 本文件是 Issue #16「支持本地 agent 和框架的明确」的架构八步产物留痕。
> 场景对象：**为 dongjiagoushi 补齐"本地 Agent"能力** —— 让同一套「架构师 + 多角色团队」既能被云端 `@CodeBuddy` 触发，也能在**本地无 `@` 环境下**作为可下载、可运行的 Agent 使用。
> 执行角色：架构·总师（官方 @CodeBuddy 化身）
> 期望终态：**形成一个团队** —— 产品经理(沟通对接/翻译意图/拆需求) → 架构师(确认版本/校验正确性/合理性/成本/周期) → **经理(分配调度核心：拆任务/派活/排期/跟进度/升级阻塞)** → 协同 agent（小组长/审查/对齐版本/找工具/测试）→ 用户提交请求后自动编排到交付。

---

## ⏸CP0 · 需求澄清摘要
- **目标**：补齐本地 Agent 能力，使架构师团队不依赖 CNB 平台 `@` 触发也能在本地运行；形成"需求→产品→架构→**经理调度**→多角色协同→交付"的三核心协作闭环（产品沟通为开始 / 架构师为设计核心 / 经理为分配调度核心）。
- **边界**：本次落地本地 Agent 的**可运行骨架 + 团队编排契约 + 架构方案**；真实 LLM 推理由接入的模型提供（本地兼容多种后端）。
- **验收标准**：
  1. 本地可通过命令行触发任意角色（替代 `@`）；
  2. 用户提交需求后自动编排"产品→架构→**经理调度**→协同→交付"流水线；
  3. 多角色（经理/小组长/审查/对齐版本/找工具/测试）有明确输入/输出契约；
  4. 与云端 `@CodeBuddy` 共享同一套角色定义与接力/回转/打断协议；
  5. 本地有测试可复现。
- **关键不确定项**：本地模型的接入方式（需做多后端抽象，默认兼容 OpenAI/兼容 CLI 工具）。

## 1/8 调研报告

### 人类需要什么能力
- 在不登录 CNB / 无 `@` 的环境下，也能唤起架构师团队干活；
- 一条命令提交需求，团队自动编排到交付，人类只做俯瞰与 CP 确认；
- 可下载、可本地跑、可离线用。

### AI 需要什么能力
- 一个**本地入口**（CLI/脚本）承载"@触发"语义：`--role <角色> "<需求>"`；
- 同一套角色人设 + 接力卡 + 回转/打断协议（与 `AGENTS.md`/`SKILL.md`/`settings.yml` 对齐）；
- 一个**编排引擎**：把"需求→产品→架构→**经理调度**→协同→交付"流水线解析为步骤，逐步调度角色；
- 每个角色是可加载模块（人设 + 输入契约 + 输出契约），可独立演进。

### 参考方案与取舍
| 方案 | 说明 | 取舍 |
|------|------|------|
| 平台 `@CodeBuddy` | 云端评论触发，自动加载 SKILL | 本地不可用（无 `@`）→ 需本地等价物 |
| 独立本地 Agent CLI | 一条命令触发角色/流水线 | ✅ 采用：`local-agent/`，把 `@` 翻译成子命令 |
| 编排引擎 | 串并行调度角色、管理接力卡/状态 | ✅ 采用：`orchestrator.py` |
| 多模型后端抽象 | 本地接模型推理 | ✅ 采用：默认兼容 OpenAI 兼容接口 + CLI 工具兜底 |
| LLM 本地化（ollama 等） | 完全离线 | 🟡 预留适配器，默认仍走 API（先保证跑通） |

## 3/8 可行性验证
| 关键假设 | 结论 | 验证/规避 |
|----------|------|-----------|
| 用 CLI 子命令替代 `@` 触发 | ✅ 可行 | `--role <角色> "<需求>"` 语义等价 `@<角色> 需求`；`--pipeline <name>` 一键编排团队流水线 |
| 团队流水线可被编排引擎串起 | ✅ 可行 | orchestrator 按 `team.yaml` 的 `pipeline.steps` 顺序调度；每步输出写入接力卡，供下一步消费 |
| 本地无 `@` 时角色如何被识别 | ✅ 可行 | 用 `--role` 显式声明 + `--pipeline` 语义触发（对应云端的"显式[触发]/语义触发"） |
| 多模型后端 | 🟡 有风险 | 默认走 OpenAI 兼容 API；未配置 key 时降级为**契约生成/占位执行**（产出结构化接力卡，不假执行推理），保证流水线骨架可跑通；ollama 预留适配器 |
| 与云端共享角色定义 | ✅ 可行 | 角色人设从 `AGENTS.md`/`settings.yml`/`SKILL.md` 抽取为 `roles/*.yaml`，两侧同源 |

## 4/8 工程实施方案

```
local-agent/
├── run.py                 # ⭐ 本地入口：--role / --pipeline / --resume / --init-team
├── team.yaml              # 团队角色清单 + 流水线步骤定义
├── orchestrator.py        # 编排引擎：需求→流水线→接力卡→交付
├── relay.py               # 接力卡：进度/回转/打断 持久化
├── llm/
│   ├── __init__.py
│   ├── base.py            # 模型后端抽象
│   ├── openai_compat.py   # OpenAI 兼容后端（默认）
│   └── cli_fallback.py    # CLI 工具兜底/占位（无 key 时产出契约不假执行）
├── roles/
│   ├── __init__.py
│   ├── product.py         # 架构·产品：沟通对接/澄清/翻译意图/拆需求
│   ├── architect.py       # 架构·总师：架构设计/校验正确性/合理性/成本/周期
│   ├── manager.py         # ⭐ 架构·经理：分配调度核心（拆任务/派活/排期/跟进度/升级阻塞）
│   ├── team_lead.py       # 架构·小组长：子任务细化+协调
│   ├── developer.py       # 架构·开发：实现/自测
│   ├── reviewer.py        # 架构·评审：五维评审
│   ├── version_keeper.py  # 架构·对齐：版本对齐
│   ├── tool_finder.py     # 架构·找工具：工具检索
│   └── tester.py          # 架构·测试：测试信号灯
├── state/                 # 接力卡持久化目录（gitignore）
└── tests/
    └── test_local_agent.sh # 流水线编排 + 接力 + 回转 可复现测试
```

### 接口契约
- `run.py --role 架构·产品 "需求"` → 执行单角色并输出其契约结果
- `run.py --pipeline full --req "需求"` → 一键跑完整团队流水线到交付
- `run.py --resume` → 从接力卡 `当前进度` 续跑（对应云端 `[打断]` 续跑）
- 接力卡字段：`step / role / input / output / status / current_progress / next_step / revert_to`

## 5/8 分工与协作规则（团队角色 + 流水线）

| 流水线步骤 | 角色 | 输入 | 输出契约 | 对应云端 |
|-----------|------|------|----------|----------|
| 1 需求澄清 | 架构·产品 | 用户需求 | 用户故事+验收标准+边界+反问 | `[触发:架构·产品]` |
| 2 架构设计 | 架构·总师 | 需求澄清 | 架构方案+版本+校验(正确性/合理性/成本/周期) | `[触发:架构·总师]` |
| 3 分配调度 | **架构·经理** | 架构方案 | **任务拆解+角色分配+调度编排+进度跟踪** | `[触发:架构·经理]` |
| 4 小组协调 | 架构·小组长 | 任务清单 | 子任务细化+协调 | `[触发:架构·小组长]` |
| 5 实现 | 架构·开发 | 子任务 | 代码+自测+PR | `[触发:架构·开发]` |
| 6 评审 | 架构·评审 | 改动 | 五维评审 分级 | `[触发:架构·评审]` |
| 7 版本对齐 | 架构·对齐 | 版本线 | 版本一致性校验 | `[触发:架构·对齐]` |
| 8 找工具 | 架构·找工具 | 任务需求 | 工具/依赖清单 | `[触发:架构·找工具]` |
| 9 测试信号灯 | 架构·测试 | 全量交付 | 测试矩阵+信号灯 | `[触发:架构·测试]` |
| 10 交付 | 编排引擎 | 全部 | 交付报告 | — |

- **回转协议**：下游输出 🔴必修/🔴阻塞 → 接力卡写 `revert_to` + `reason`，编排引擎回退到指定步骤重跑（对应云端 `[回转]`）。
- **打断协议**：任何步骤中断 → 接力卡写 `current_progress`+`next_step`，`--resume` 续跑（对应云端 `[打断]`）。

## 8/8 汇报与复盘
- **决策摘要**：以 CLI 子命令承载 `@` 语义 + 编排引擎把团队流水线串成"需求→交付"闭环；角色与云端同源、复用接力/回转/打断协议；模型后端多抽象、无 key 降级占位保证骨架可跑通。
- **风险清单**：
  - [MEDIUM] 本地真实 LLM 推理依赖模型后端 → 规避：无 key 时降级为"契约生成+占位"，流水线骨架不假执行。
  - [MEDIUM] 本地与云端角色可能漂移 → 规避：`roles/*.py` 与 `settings.yml`/`SKILL.md` 显式同源并加一致性测试。
- **复盘**：本次用"架构八步"设计自身缺失能力，验证了八步链路对"迭代自身"同样适用——与 PR #14 自审查结论一致（框架可通、可自演进）。
