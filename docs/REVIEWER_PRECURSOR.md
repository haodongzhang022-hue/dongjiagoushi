# 审核者前置助手（Reviewer Precursor）· 决策补全机制

> 本文件是 Issue #31「层间协作」设计闭环的落地文档。
> 融合了本仓库多轮讨论的所有修正，其中最后两条（L5 自决能力 + 功能验证判定口径）
> 由人类（山东予路 张浩东）拍板确认，是本文档的最终口径。

## 一、定位与触发时点

「审核者前置助手」不是又一个常驻流程角色，而是一个**在「产生二选一 / 两者都不够好」疑问的瞬间触发的决策补全机制**。它解决的核心认知问题：**架构对话里大量「A 还是 B」的提问，底层不是二选一，而是 A、B 都不完整，正确答案藏在 A、B 之外的并集 / 补集里**。

它按「3 层时点 + 5 类 or 分支」运作，越往后越看向外部、越接近人类判断。

| 层 | 触发时点 | or 分支 | 动作 |
|---|---|---|---|
| **L1 决策瞬间** | 产生「A or B 都不够好」的疑问 | ① 合并保留·区分场景 ② 加约束 ③ 换道 ④ 补集 | 向内摊开被忽略的内部方案 |
| **L2 全部落空** | ①②③④ 走完仍无解 | **⑤ 开放探索型（新增）** | 看向外部：搜索公开最优解（开源 / 插件 / skill / 论文） |
| **L3 交人判断** | 外部搜索也无显性最优解，或命中方案带成本/安全风险 | ⑤→ 带着问题 + 探索信息给人类 | 人类拍板，人类自己选的自己接受 |

> 总纲：**①②③④ 是"向内摊开被忽略的路"，⑤ 是"向外找现成的路"，都找不到或要担责才到人类。**

## 二、⑤ 开放探索型 —— 有自决能力，不是只收资料

> 本条由人类拍板修正：**审核者前置助手不能只做"收集资料直接给人类"，它要能在部分场景下完成决策功能。**

⑤ 开放探索型的执行规则如下：

1. **带明确的检索问题定义** 去搜公开最优解（开源项目 / 插件 / skill / 论文 / 同类成熟方案）。
2. **命中且风险可控 → 直接自决**：若找到的现成方案 **负面足够小、无成本、无安全风险**，则**直接采纳使用**（完成决策功能），不推给人类。
3. **命中但需担责 → 交人类审核**：若方案带 **成本 / 安全风险 / 负面不够小**，则进入 **L3 交人判断**，把方案 + 代价 / 风险显式摊开，由人类拍板——**人类作为"背锅侠"承接责任**（自己选的自己接受，agent 不背锅、不代替）。
4. **未命中显性最优解 → 交人类判断**：把探索过程中发现的信息（相近方案 / 行业做法 / 论文方向）整理成**"判断素材包"**给人类，由人类一起判断，不直接拍板。

**自决与交人的分界（关键）**：分界不是"能不能找到方案"，而是 **"是否要担责"**——负面足够小 / 零成本 / 零安全风险时 agent 直接自决；一旦涉及成本 / 安全 / 明显责任，必须交人类审核（人类是背锅侠）。

## 三、判定口径 —— 以「功能验证是否通过」为准，不以「做了判断」为准

> 本条由人类拍板修正：**能不能解决不是决策直接判断的，而是决策选择方案后，方案实施是否足够解决了之前分配的任务/功能——即功能验证是否通过。**

修正后，任何一次决策 / 会诊 / 补位都不再是"终局"，而是一环尝试。判定的唯一口径是**分配给该处的任务 / 功能是否被实施结果真正达成**：

```
起点: 方案为"当前假设"，执行中可持续修正，不把任何一次判断当终局
  ├─ 单兵主战
  ├─ 卡点/专长缺口 → 差异 agent 按触发时机补位
  ├─ 疑难/多项解决不掉/对错难辨 → 【专家会诊】（会诊是有信号可判的）
  │     ├─ 会诊后功能验证通过 ✅ → 放行
  │     └─ 会诊结束仍不通过 → 【审核者前置助手】（进入 L1→L2→L3）
  │           ├─ L1 内部分支 ①②③④ 解决 → 功能验证通过 ✅ → 放行
  │           ├─ L2 外部探索 ⑤ 找到现成方案且风险可控 → 直接自决 ✅ → 放行
  │           └─ L3 仍无法通过 → 按下方"功能未达成"链路上报
  └─ 全程以"功能验证是否通过"为准
```

### 功能未达成时的链路（判定口径的完整闭环）

当某个任务/功能的**功能验证不通过**时，按序推进，能多自动一环就多自动一环：

1. **先问总师是否做架构调整**：是否需要对架构做局部调整来达成该功能。
2. **不适合调整但必须做成 → 折中方案 / 取舍**：在既有约束下给出折中 / 取舍方案。
3. **折中后仍解决不掉 → 询问人类**：带着问题 + 探索信息 + 折中选项给人类拍板。

## 四、触发与协作纪律

- **触发**：显式 `[触发:架构·审核前置助手]`；语义命中「两个都不够好 / 二选一 / 拿不准 / 分歧 / 解决不掉 / 换方案 / 开源 / 现成方案 / 背锅」；或 rules 固定（凡出现"二选一疑问 / 会诊后仍不通过"即触发）。
- **不越权**：它是**决策补全机制**，不是"替谁做决定"。能自决时自决（⑤ 风险可控分支），需担责时交人类，绝不代替人类拍板责任归属。
- **留痕**：每次触发的 5 类 or 分支选择、是否命中外部方案、是否自决/交人，均须在 Issue/评论留痕可核验。
- **与专家会诊衔接**：会诊解决不了 → 审核者前置助手（L1→L2→L3）；审核前置解决不了 → 人类。每环独立检查点。

## 五、与既有机制的关系

| 既有机制 | 与审核者前置助手的关系 |
|---|---|
| 跨岗位 DAG 接力卡 | 保留；审核前置助手作为"疑难分支"上的补全环节接入 |
| 差异化单兵 + 触发补位 | 保留为主机制；审核前置只在前 4 类补位 / 会诊都不通时触发 |
| 专家会诊（共识表决） | 保留为"疑难 / 多解 / 对错难辨"场景工具；会诊结束≠终局 |
| 规模预设（Size Preset） | 前期辅助角色组在澄清阶段完成，作为增减基准锚点 |
| 架构师 3 阶段渐进 | 粗纲→功能域→细纲，每阶段独立检查点 |
| 经验方案库（Pattern Lib） | 接 `src/memory`，沉淀成功 / 失误修正 / 加量三类路径复用 |
| 哨兵（目标收敛监控） | 对协作组做收敛监控；"功能验证不通过"即为明确未收敛信号 |

## 六、完整决策总纲（一图收口）

```
前期辅助角色组：默认 1 个，按需增减（秘书/产品/架构师/助理/调研/销售/客服按场景编成）
   ↓
架构师 3 阶段渐进：粗纲 → 功能域 → 细纲（每层独立检查点，错误早暴露）
   ↓
任务执行：方案为假设，执行中可修正
   ├─ 默认 → 差异化单兵主战，按规则补需求
   ├─ 卡点/专长缺口 → 差异 agent 按触发时机补位
   ├─ 疑难/多解/对错难辨 → 【专家会诊】（会诊结束≠终局）
   │     └─ 会诊后功能验证不通过 → 【审核者前置助手】
   │           ├─ L1 内部分支：①合并保留·分场景 ②加约束 ③换道 ④补集
   │           ├─ L2 外部探索：⑤ 搜开源/插件/skill/论文现成方案
   │           │     ├─ 命中且负面小/零成本/零安全风险 → 直接自决 ✅
   │           │     └─ 命中但带成本/安全风险 或 未命中 → 进 L3
   │           └─ L3 交人判断：带问题+探索素材包/方案+代价给【人类】拍板
   └─ 功能验证不通过链路：问总师是否架构调整 → 不合适则折中/取舍 → 仍不通过则询问人类
```
