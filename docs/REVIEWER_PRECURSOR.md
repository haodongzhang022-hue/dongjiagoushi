# 审核者前置助手（Reviewer Precursor）· 决策补全机制

> 本文件是 Issue #31「层间协作」设计闭环的落地文档。
> 融合了本仓库多轮讨论的所有修正，其中最后两条（L5 自决能力 + 功能验证判定口径）
> 由人类（山东予路 张浩东）拍板确认，是本文档的最终口径。

## 一、定位与触发时点

「审核者前置助手」不是又一个常驻流程角色，而是一个**只在「功能实现不了」时才触发的决策补全环节**。它解决的核心认知问题：**架构对话里大量「A 还是 B」的提问，底层不是二选一，而是 A、B 都不完整，正确答案藏在 A、B 之外的并集 / 补集里**。

> ⚠️ **触发时机（本条硬约束）**：本机制**不是常态化的主流程**，而是**功能实现不了时才接入的一小段决策补全链路**，前置环节（单兵 → 补位 → 专家会诊）**一个都不能丢**——缺前置就接入本机制属于**错误**。本机制只是完整链路中的一小部分，不替代主链路。

它按「3 层时点 + 5 类 or 分支」运作，越往后越看向外部、越接近人类判断。

| 层 | 触发时点 | or 分支 | 动作 |
|---|---|---|---|
| **L1 决策瞬间** | 产生「A or B 都不够好」的疑问 | ① 合并保留·区分场景 ② 加约束 ③ 换道 ④ 补集 | 向内摊开被忽略的内部方案 |
| **L2 全部落空** | ①②③④ 走完仍无解 | **⑤ 开放探索型（新增）** | 看向外部：搜索公开最优解（开源 / 插件 / skill / 论文） |
| **L3 交人判断** | 外部搜索也无显性最优解，或命中方案带成本/安全风险 | ⑤→ 带着问题 + 探索信息给人类 | 人类拍板，人类自己选的自己接受 |

> 总纲：**①②③④ 是"向内摊开被忽略的路"，⑤ 是"向外找现成的路"，都找不到或要担责才到人类。**

## 二、⑤ 开放探索型 —— 有自决能力，不是只收资料

> 本条由人类拍板修正：**审核者前置助手不能只做"收集资料直接给人类"，它要能在部分场景下完成决策功能。**

⑤ 开放探索型的执行规则如下：

1. **带明确的检索问题定义** 去搜公开最优解（开源项目 / 插件 / skill / 论文 / 同类成熟方案）。
2. **命中且风险可控 → 直接自决**：若找到的现成方案 **负面足够小、无成本、无安全风险**，则**直接采纳使用**（完成决策功能），不推给人类。
3. **有负面责任需决策 → 人类结果前置（不是背锅才到人）**：若方案带 **成本 / 安全风险 / 负面不够小**，**在做出这个决策的那一刻**就要请人类出来拍板——**结果前置、因果对齐**。交给人类时信息必须**足够明确**，尤其**把风险点显式列清**（是什么风险、发生在哪一步、代价多大、有无兜底），让人类在**决策点**（而非事后）就掌握全部因果，从而自己选择、自己承担。agent 不背锅、不代替、不等到做完才叫人。
4. **未命中显性最优解 → 交人类判断**：把探索过程中发现的信息（相近方案 / 行业做法 / 论文方向）整理成**"判断素材包"**给人类，由人类一起判断，不直接拍板。

**自决与交人的分界（关键）**：分界不是"能不能找到方案"，而是 **"是否要担责"**——负面足够小 / 零成本 / 零安全风险时 agent 直接自决；一旦涉及成本 / 安全 / 明显责任，**在决策那一刻就把人类叫出来**（结果前置），让人类在因果对齐、信息足够明确的前提下拍板。

**补充口径（AI 的办法不等于终局）**：**AI 判断"没办法"，不一定是真没路**——换个问法 / 问一下别人，答案可能不一样。因此：
- 不能因为"AI 觉得没有更明显的更好方案"就把该处**直接定性为终局**而挡在决策链之外。
- 若**补充信息后仍无更明显更好的方案**，但该做法属**必要成本**（不做就完不成目标），**也可做，但必须人类确认**——同样走结果前置，信息足够明确、风险点列清，由人类点头后才执行。

## 三、判定口径 —— 以「功能验证是否通过」为准，不以「做了判断」为准

> 本条由人类拍板修正：**能不能解决不是决策直接判断的，而是决策选择方案后，方案实施是否足够解决了之前分配的任务/功能——即功能验证是否通过。**

修正后，任何一次决策 / 会诊 / 补位都不再是"终局"，而是一环尝试。判定的唯一口径是**分配给该处的任务 / 功能是否被实施结果真正达成**。本机制**不是独立完整链路**，而是完整链路中的一环——**前置（单兵→补位→会诊）必须保留，缺前置即错误**：

```
起点: 方案为"当前假设"，执行中可持续修正，不把任何一次判断当终局
  ├─ 单兵主战
  ├─ 卡点/专长缺口 → 差异 agent 按触发时机补位
  ├─ 疑难/多项解决不掉/对错难辨 → 【专家会诊】（会诊是有信号可判的）
  │     ├─ 会诊后功能验证通过 ✅ → 放行
  │     └─ 会诊结束仍不通过 → 【审核者前置助手】（仅此一小段，前置不丢）
  │           ├─ L1 内部分支 ①②③④ 解决 → 功能验证通过 ✅ → 放行
  │           ├─ L2 外部探索 ⑤ 找到现成方案且风险可控 → 直接自决 ✅ → 放行
  │           └─ L3 仍无法通过 → 按下方"功能未达成"链路上报
  └─ 全程以"功能验证是否通过"为准；本机制只是其中一环，不是完整链路
```

### 功能未达成时的链路（判定口径的完整闭环）

当某个任务/功能的**功能验证不通过**时，按序推进，能多自动一环就多自动一环。**前置条件（单兵 → 补位 → 专家会诊 → 审核前置）一路都不能丢**；且**不是一有错误就直接推到总师改错**：

1. **先看是否有其他实现方式（到小组长，不是直接到总师）**：功能未达成时，**一般先到小组长**，由小组长判断是否有**其他实现方式 / 可尝试的解决路线**——在既有分工内先自行尝试解决，能解决就解决，不急着惊动总师。
2. **此前一般由哨兵量化触发（不是一有错误就让总师改错）**：这个阶段**通常是「目标进度尺推进不动」（哨兵的量化距离停滞）**才触发升级，而不是每出现一个错误就让总师来改——普通错误在小组内消化，推进不动才往上升。
3. **小组长尝试解决仍无法达成 → 才到总师**：小组长在既有实现方式上已尝试、仍无法达成，才把问题上升到总师，由总师判断**是否做架构调整**。
4. **不适合调整但必须做成 → 折中方案 / 取舍**：在既有约束下给出折中 / 取舍方案。
5. **折中后仍解决不掉 → 询问人类（结果前置）**：带着问题 + 探索信息 + 折中选项给人类拍板，**信息足够明确、风险点列清**，在决策点让人类拍板（而非事后背锅）。

**专角色专用（保总师上下文纯净）**：较大任务下，为确保总师上下文纯净，**修改框架 / 改错的部分可设置一个总师岗位的单独角色**（如「架构·总师助理 / 改框架专项」），**专门负责改错改框架**，专角色专用——不让框架修改污染总师主线的决策上下文；该专项角色向总师汇报、由总师把关，但仍独立承担框架修正工作。

## 四、触发与协作纪律

- **触发时机**：**只在功能实现不了时接入本链路**，且前置（单兵 → 补位 → 专家会诊）必须已走过——缺前置直接触发属错误。触发：显式 `[触发:架构·审核前置助手]`；语义命中「两个都不够好 / 二选一 / 拿不准 / 分歧 / 解决不掉 / 换方案 / 开源 / 现成方案」；或 rules 固定（凡出现"二选一疑问 / 会诊后仍不通过"即触发）。
- **不越权**：它是**决策补全机制**，不是"替谁做决定"。能自决时自决（⑤ 风险可控分支），需担责时交人类，绝不代替人类拍板责任归属。
- **留痕**：每次触发的 5 类 or 分支选择、是否命中外部方案、是否自决/交人，均须在 Issue/评论留痕可核验。
- **与专家会诊衔接**：会诊解决不了 → 审核者前置助手（L1→L2→L3）；审核前置解决不了 → 人类。每环独立检查点。

## 五、与既有机制的关系

| 既有机制 | 与审核者前置助手的关系 |
|---|---|
| 跨岗位 DAG 接力卡 | 保留；审核前置助手作为"疑难分支"上的补全环节接入 |
| 差异化单兵 + 触发补位 | 保留为主机制；审核前置只在前 4 类补位 / 会诊都不通时触发 |
| 专家会诊（共识表决） | 保留为"疑难 / 多解 / 对错难辨"场景工具；会诊结束≠终局 |
| 规模预设（Size Preset） | 前期辅助角色组在澄清阶段完成，作为增减基准锚点 |
| 架构师 3 阶段渐进 | 粗纲→功能域→细纲，每阶段独立检查点 |
| 经验方案库（Pattern Lib） | 接 `src/memory`，沉淀成功 / 失误修正 / 加量三类路径复用 |
| 哨兵（目标收敛监控） | 对协作组做收敛监控；"功能验证不通过"即目标推进不动的明确未收敛信号，由此触发升级（先小组长，再总师），而非一有错误就惊动总师 |
| 小组长（整合/分形） | 功能未达成**先到小组长**，看有无其他实现方式/尝试解决路线；小组长解决不了才上升到总师 |
| 总师助理（专角色专用） | 较大任务下保总师上下文纯净：**专门负责改错改框架的单独角色**，专角色专用，向总师汇报但独立承担框架修正 |

## 六、完整决策总纲（一图收口）

```
前期辅助角色组：默认 1 个，按需增减（秘书/产品/架构师/助理/调研/销售/客服按场景编成）
   ↓
架构师 3 阶段渐进：粗纲 → 功能域 → 细纲（每层独立检查点，错误早暴露）
   ↓
任务执行：方案为假设，执行中可修正
   ├─ 默认 → 差异化单兵主战，按规则补需求
   ├─ 卡点/专长缺口 → 差异 agent 按触发时机补位
   ├─ 疑难/多解/对错难辨 → 【专家会诊】（会诊结束≠终局）
   │     └─ 会诊后功能验证不通过 → 【审核者前置助手】——⚠️ 只此一小段，前置不丢、非完整链路
   │           ├─ L1 内部分支：①合并保留·分场景 ②加约束 ③换道 ④补集
   │           ├─ L2 外部探索：⑤ 搜开源/插件/skill/论文现成方案
   │           │     ├─ 命中且负面小/零成本/零安全风险 → 直接自决 ✅
   │           │     └─ 命中但带成本/安全风险 或 未命中 → 进 L3
   │           └─ L3 交人判断：带问题+探索素材包/方案+代价给【人类】拍板（结果前置，风险点列清）
   └─ 功能未达成链路（哨兵量化推进不动触发，非一有错误就到总师）：
       先到小组长看其他实现方式/尝试解决路线 → 仍不达成才到总师判断架构调整
       → 不合适则折中/取舍 → 仍不通过则询问人类；
       较大任务下改错改框架由「总师助理」专角色专用承担，保总师上下文纯净
```
