# ADR-0020：桥接交付物必须「句柄自足」，不是只传一个 id

- 状态：Accepted
- 决策日期：2026-09（Issue #232）
- 相关：`local-agent/entries/bridge.py`、`docs/PLATFORM_ADAPTERS.md` 三.6.1、ADR-0007

## 背景
用户实测：本地发起的云开发请求，交付时只带了**一个桥接句柄 id**；本地服务一关，云端拿着 id
什么也做不了。三条根因：
1. 跨端实际传输的只有 `handle_id` + 首行 40 字 `req_key`，上下文留在本地
   `entries/_bridge_state/`，而该目录**本就不进版本库** → 云端读代码也读不到；
2. `local_test_first` 的 mock 执行器恒返 `ok=True`、脚本不存在也不报错 → 云端把"没跑"当"过了"；
3. `locus` 只是一个标签，没有按动作判定「云端能做 / 必须本地 / 必须人工」。

## 决策
1. **交付物必须自足**：凡跨执行地交付，必须给「一个 id 就能重建上下文」的**自足卡**
   （目的/验收/不做边界/所在仓库+issue+PR/脑区/证据缺口/自检清单），并**卡自带合规接力卡标记**
   （完整 `@org/repo(角色)` + `[触发:角色全称]`），由 `relay_card.check` 机器校验，不靠自觉。
2. **残卡机器拦截**：`verify_handle_card` 判缺项即不达标，不静默交付。
3. **脑区判定先于能力判断**：判定口径是「在哪能做」而非「能不能做」——云端做开发/评审/CI，
   本地测试与对齐必须本地可达，合并卡人类；未知动作宁拦不放。
4. **证据保全**：本地不可达时返回 `evidence_available=False` + 缺口清单，**绝不把"没数据"
   当成"没问题"**；本地可达后凭句柄补跑，不迁移到云端（云端建环境贵）。
5. **不许假绿灯**：本地测试默认只出计划；真跑以 rc 为准，rc 非 0 / 脚本缺失必须 `ok=False`。

## 后果（权衡）
- 好处：断链不再让云端"空手"；「信息不全」从口头约定变成可执行闸门；本地/云端责任边界显式。
- 代价：交付要多写约 10 行骨架（可 `--bridge render` 一键生成，成本近零）；句柄卡可能含本地
  信息，交付时需脱敏（本仓规则：不落 token/密钥）。
- 边界：本 ADR 只管「跨执行地交付形态」，不管桥的传输实现（传输仍是注入式 transport，见 ADR-0007）。
