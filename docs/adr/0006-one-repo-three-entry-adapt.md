# ADR-0006：三执行入口收敛为「一套仓库 + 多层适配 + 配置管差异」，不拆 3 个仓库

- 状态：Accepted
- 决策日期：2026-09
- 相关：Issue #105（三入口归一化）、`docs/PLATFORM_ADAPTERS.md` 三.5、`local-agent/entries/`

## 背景
用户在 PR #104 评论区提出：「网页对话驱动本地和云端 / cnb.cool / 本地 AI 三个，谁当入口」
——三个入口对应链条不完全一样，问是条件处理还是拆 3 个仓库。若拆 3 个仓库，开发时难以对齐。

## 决策
三个执行入口（网页对话 / cnb.cool 云端 NPC / 本地 harness-AI）**不是 3 个产品**，而是
「入口 + 执行地」组合。收敛为 **一套仓库 + 多层适配 + 配置管差异**：
- **主入口锁死「架构·秘书」**：三入口都是「把话送到秘书面前」的通道，主入口永远一个（秘书→路由），
  其余只是触达方式——`guard_entry` 强制护栏承载。
- **差异收口到「适配层 + 执行地」两维度，做配置不做硬编码**：入口适配（web/cnb/local）各自实现
  最小宿主接口 `trigger/read_card/run_dag/scale_swarm`（`local-agent/entries/`），
  本地 vs 云端执行走 `CLOUD_LOCAL_COOP.md` 分工边界。
- **核心编排仅一份、无入口 if 分支污染**：三模式用「可插拔适配器 + 配置」承载，不把
  `if (入口==网页)` 塞进 core。

## 后果（权衡）
- 好处：一套核心规则、多宿主稳定运行，避免 3 仓库开发对齐地狱；差异可视、可配置、可独立演进。
- 代价：需要维护适配层（抽象成本）与执行地分工纪律；若把适配差异误升级成「分支/产品差异」会散架
  （已明确 3 仓库方案为反面、不采纳）。难反转，记 ADR。
