# ADR-0010：通用架构师的能力底座 = 专家层 + AI 前沿 + 帕累托 + 外部验证

- **状态**：Accepted（2026-11-03）
- **决策者**：人类（dongdong）+ 架构·总师
- **相关**：`docs/EXPERT_ARCHITECT.md`、`local-agent/expertise/`、`docs/ARCHITECTURE.md`、ADR-0004（能力全员化）

## 背景

「通用架构师」此前被理解为「能接任何行业的架构设计」。实测问题：

1. 产出看起来完整，但**判断不可信**：行业差异靠模型模糊印象，AI 能力边界靠过时认知；
2. **无法证伪**：没有外部验证，评审只能评"写得像不像"；
3. **选型无比较**：常常直接给一个方案，没有备选，也无从解释"为什么不是另一个"；
4. **信息无时间戳**：引用的事实可能已过期，却被当成当前事实使用。

用户明确要求：不要笼统架构师觉得全能做了，要建立在**行业岗位专家**与**AI 发展前沿**之上，
按 **高度/深度/广度/资源/实现路径/帕累托最优/外部验证** 判断，且外部验证尤其指**功能性代码验证门禁**，
信息要**注意时效性**。

## 决策

新增独立模块 `local-agent/expertise/`，作为「专家级」的**能力底座**，四支柱 + 一闸门：

1. `experts.py` —— 消费 `hanghangchuzhuangyuan` 行业/岗位注册表（不复制数据，唯一事实源在对方）；
2. `ai_frontier.py` + `data/ai-frontier.yaml` —— 能力前沿带 `state`/`dated_at`/`source`/`next_problem`；
3. `pareto.py` —— 多目标支配/前沿/分层/可解释取舍；
4. `external_validation.py` —— 真实执行验证 + 反造假核验 + 功能性判据；
5. `freshness.py` —— 按信息类型设陈旧上限，无日期/无来源即不可用；
   统一由 `evaluator.py` 合成七维 `verdict`（`spec.py` 是唯一事实源）。

同时新增 `issue_contract.py`：把「Issue 身份唯一 + 幂等派发 + 收并」变成结构性约束
（见 `docs/ISSUE_CONTRACT.md`）。

## 关键取舍（刻意为之，勿轻易"修正"）

| 取舍 | 理由 |
|---|---|
| **七维全部必过**（缺一即 inadmissible） | 少一维的判断就是不可信判断；放宽会让"看起来完整"的方案蒙混 |
| **外部验证权重最高 0.20** | 它是唯一能**证伪**结论的一维；其它六维都是自述 |
| **只认真实执行证据**（忽略 `verified` 自述字段） | 不如此则"我已验证"成为万能通行证 |
| **静态检查不算功能验证** | `grep`/`test -f` 证明长得像，不证明能跑 |
| **跨目标签名的候选互不支配** | 用不完整目标集下支配断言 = 静默淘汰方案；宁可都留在前沿 |
| **候选 <2 判不可信** | 没有备选就没有前沿，"唯一方案"不构成选型 |
| **无日期 = 不可信（undated→不可用）** | 无法证明时效 = 不得作为决策依据 |
| **未收录能力判 `unknown` 而非"能做"** | 默认放行会让架构师回到"全能幻觉" |
| **专家层不可用 → `unverified` 降级** | 判不出来 ≠ 通过（唯一事实纪律） |
| **issue_contract 不直连网络** | 只产出动作与证据，可本地单测、可 dry-run、不可逆动作交人 |
| **不批量改历史标题，只收并关闭** | 改名破坏外部引用；审计痕迹应保留 |

## 后果

**正向**：
- 架构结论可核验：每个判断都有维度证据、前沿比较与真实执行记录；
- 陈旧信息不会静默污染决策（会被快速判 stale）；
- Issue 空间不再无限增长垃圾（幂等 + 契约拦截）。

**代价 / 风险**：
- `data/ai-frontier.yaml` 需人工维护，不更新就静默失效（已自标为 `emerging` 风险）；
- 专家层仅 14 行业，未覆盖行业须走"补单元"而非硬凑；
- Windows 下 `hanghangchuzhuangyuan` 整包不可导入（POSIX `fcntl`），本模块按文件加载绕开 ——
  这依赖对方的 `models.py`/`registry.py` 相对稳定，若对方重构需同步；
- 外部验证依赖命令可执行，环境缺依赖时判 fail（不会假装通过）。

## 备选方案（已否决）

| 方案 | 否决理由 |
|---|---|
| 把所有判定写进 SKILL.md 提示词 | 提示词不可确定性验证，无法红灯；且易被后续 agent"改好一点"漂移 |
| 复用 `review_metrics` 五维代替七维 | 两者正交：那是"评审有效性"，这是"架构判断完整性"；混用会产生第二套正本 |
| 自建行业专家数据 | 违反唯一事实源；`hanghangchuzhuangyuan` 已是正本，复制即分叉 |
| 依赖 LLM 判断"够不够专家级" | 不可复现、不可审计；必须确定性代码判定 |
