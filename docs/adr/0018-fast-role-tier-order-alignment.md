# ADR-0018：快档角色档序服从人类拍板，不以「异于默认」定义快档语义

- 状态：Accepted（补齐 ADR-0017 未落到快档角色的缺口）
- 决策日期：2026-10-21
- 相关：Issue #199、Issue #202（收尾）、ADR-0016、ADR-0017、`docs/MODEL_ROUTING.md`

## 背景

ADR-0017 把档序定成 `deepseek-v4.1-flash → minimax-3.1-flash → codebuddy →
glm-5.3-flash`，但它只改对了**默认链**，漏了写进 `roles` 的 3 个「快档角色」
（架构·开发 / 架构·进度推手 / 市场·客服）——这三条链的首档仍是被拍板否掉的
`glm-5.3-flash`，等于**人类定了「deepseek 第一」，最快的那三个角色却从 glm 起跑**。
测试 `test_model_role_assign.sh` 当时还把这个错序写成了断言（"快档角色主档应为
glm-5.3-flash"），把错误固化下来。

同时暴露出一个概念冲突：`is_fast_role()` 的原判据是「首档**异于**默认链首」。
人类把第一优先定成默认链首后，这条判据会让所有快档角色恒为 `False`——语义自相矛盾，
并连带让「空壳链」审计（链与 fallback 逐字相同即判空壳）把快档角色误判成空壳，
制造「删了又加」的抖动。

## 决策

1. **快档角色档序一律服从人类拍板**：3 个快档角色的链改为与拍板同序
   `deepseek-v4.1-flash → minimax-3.1-flash → codebuddy → glm-5.3-flash`。
   快档角色**不得自排档序**，配置注释与文档都写明出处是 Issue #199。
2. **重定义「快档角色」判据**：`is_fast_role()` = 显式写进 `roles` **且** 首档 == 快档
   第一优先（`default_chain()[0]`）**且** 末档 == `last_resort_model`。
   语义从「另排一套」变成「显式锚定快档档序」。
3. **「空壳链」判据收紧**：链与 fallback 逐字相同**且不构成快档锚定**才算空壳。
   快档角色即便档序与 default 同构，也显式承担「档1指定/档2一样/档3兜底」契约。
4. **别名断裂判据改为直接查声明**：原先靠「短名链 ≠ 规范名链」推断，档序同构后
   短名缺失会解析出同样的链、断裂无法察觉（静默盲区）。改为：显式写进 `roles` 的
   角色，其短名必须在 `role_aliases` 里登记，缺即报红。

## 后果（权衡）

- 好处：人类拍板真正落到**全部角色**，不只默认链；快档语义与空壳审计不再互相矛盾；
  别名断裂从「比不出来」变成「确定性可查出」。
- 代价：「快档角色」不再意味着「主档与别人不同」，读配置的人容易误以为这 3 条是
  冗余空壳——故在 `models.yml` 注释与本文里写明其存在理由是**锚定档序契约**。
- 未解的风险：`minimax-3.1-flash` / `glm-5.3-flash` 在平台可选列表是否真存在
  **仍未 probe 验真**（云端无 key，显式 `skipped`）。若不存在，真调时会显式报错，
  不静默——这条纪律不因本 ADR 而松。
