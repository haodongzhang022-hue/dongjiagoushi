# ADR-0001：一库多角色（单仓库承载多角色）

- 状态：Accepted
- 决策日期：2026-09
- 相关：AGENTS.md「一库多角色」、.cnb/settings.yml

## 背景
早期考虑「每个角色一个仓库」或「多仓库协同」。但多仓库会导致：跨库召唤权限断裂、
角色命名混乱、上下文传递成本高。

## 决策
采用**一库多角色**：单一仓库（`dongjiagoushi`）承载全部角色（架构·总师 + 架构·产品/开发/
评审/测试等扩展位），上下文靠接力卡稳定传递，skill 在本仓库对话自动加载。

## 后果（权衡）
- 好处：一套架构/流水线/知识库共享；迭代目标靠接力卡不偏差；角色命名带「架构·」前缀区分度高。
- 代价：仓库承载较多角色后需靠命名空间区分；跨库真正需要时靠 HandleAbility 动态定位目标仓库
  有权限角色（不写死）。本决策难反转，故记 ADR。
