# 秘书·感知能力层（SecretarySense）

Issue #41 用户核心纠偏落地：**规模匹配落位澄清阶段（非第一步、非优先级）+ 秘书价值强化（需求明确/决策博弈/测试兜底接管）**。

## 定位

秘书（架构·秘书）不只是"入口接待"，而是**需求澄清阶段的第一感知者**。用户明确：
- 选择规模不是第一步、更不是优先级；前面大概率从**秘书开始 → 到产品**，此时**评估项目层级**，据此走后续流程。
- 秘书的价值：充分了解需求 → 需求明确 → 提示词优化 → 跟产品明确细节 → 沟通对接 → 方案确定 → 确保成本与结果复合要求 → **甚至包含成果测试**。
- 常规"二选一都不够好"的犹豫，秘书因多了**信息、探索决策规则、多选项博弈、本地环境**，能解决大部分疑问；立场与后续开发不同还能**对抗博弈（对抗生成式）**。

## 三大能力

### ① 规模匹配（scale-match）· 落位澄清阶段
- 语义：不是第一步、不是优先级；而是"秘书→产品澄清时评估项目层级 → 据此走后续流程"。
- 落地：复用 `fusion.route()`（规模金字塔→承接体系→拓扑→角色子集→四套方案），在澄清阶段产出基准锚点；经理按架构做增量修正，不做从零规划、不二次评估。
- 规模档位：micro（单开发）/ small（敏捷）/ medium（加架构师）/ large（公司拉满）/ huge（完整体系+蔓延），**越小占比越高越该精简**。

### ② 决策博弈（decision-game）· 对抗生成式
- 解决"A or B 都不够好"：内部摊开 5 类 or 分支（合并保留·区分场景 / 加约束 / 换道 / 补集 / 开放探索外部最优解）。
- 对抗校验：秘书立场 ≠ 落地开发立场 → 互搏暴露各自盲区 → 收敛更稳建议（像对抗生成）。
- 本地环境探测：python 版本 / cnb 可用 / LLM 凭据等，作为"多了本地环境"的信息增量。
- 自决原则：能自决即自决；仅当承担不可逆责任/高风险时**结果前置交人拍板**（列清风险）。

### ③ 成果测试兜底接管（test-takeover）
- 语义：开发觉得完成了，测试功能时还是完全跑不通 → "想法也是继续开发，不可能存在其他说法"，**由秘书直接接管**，把"测试跑不通"作为继续开发输入交回；结果不符预期时**结果前置交人类拍板**。
- 不是放弃、不是"其他说法"顶替，就是秘书接管 + 继续开发直到功能测试真正跑通。

## 模块与接线

| 项 | 位置 |
|----|------|
| 能力模块 | `local-agent/roles/secretary_sense.py` |

## 使用

```python
from roles import secretary_sense as ss
# ① 规模匹配（落位澄清阶段）
m = ss.scale_match(complexity=0, subtasks=1)   # micro / agile / ['架构·开发']
# ② 决策博弈
r = ss.recommend("A 快但返工高，B 稳但慢，选哪个？")
# ③ 测试兜底接管
tk = ss.takeover({"status":"done"}, {"passed":False, "reason":"接口返回500"})
```

## 与现有机制协同
- **不替代** `prescale()`（团队规模/风险基准）与 `fusion.route()`（承接体系/拓扑选择），而是**在秘书澄清阶段把它们作为规模匹配落点统一产出**，经理再做增量修正。
- 与「强制入口护栏」协同：默认从秘书进入，规模匹配在秘书→产品澄清阶段完成，路由到后续角色后按其承接体系执行。
- 与「审核者前置助手」理念同源但秘书层自用：多选项博弈/探索决策/本地环境在秘书决策体系内展开，能自决即自决，需担责结果前置交人。
