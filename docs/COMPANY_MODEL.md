# COMPANY_MODEL · 公司化三战线架构（Issue #18）

> 版本：module v1.init / agent v1.init（公司化体系根版本，后续按 update/fix 独立升版）
> 归属：架构师体系 · 公司化升级（由「架构·总师」Issue #18 架构八步产出落地）

## 一、为什么公司化

原体系是"项目交付型 8 角色团队"，只覆盖「接单 → 交付」，缺"单从哪来、做什么单、做了有没有价值、做完怎么维护、能否持续开发"。公司化升级补齐这四块，让体系从「**接单做完**」升级为「**能找单、会选单、做对单、持续沉淀、长期存活**」的软件公司。

## 二、三战线拓扑

```
        ┌────────────── 市场获客线 ──────────────┐
        │  找需求 → 价值确认 → 竞品分析 → 销售 → 客服 │
        └──────────────┬────────────────────────┘
                       │ 成单需求
                       ▼
        ┌────────────── 交付流水线 ───────────────┐
        │  产品 → 总师 → 经理 → 小组长 → 开发 → 评审 → │
        │  对齐 → 测试                            │
        └──────────────┬────────────────────────┘
                       │ 交付产物/沉淀
                       ▼
        ┌────────────── 能力底座线 ───────────────┐
        │  工具开发(沉淀复用) 优化(效率)           │
        │  数据管理(数据) 运维(上线/维护)          │
        └────────────────────────────────────────┘
```

**关键洞察**：交付线产出**工具、数据、优化经验**反馈给底座线，底座线让下次交付更快 → 成本更低 → 市场更有竞争力。这是"持续开发能力 + 市场存活"的来源。

## 三、角色清单与载体落位

### 市场获客线 · 选单情报（决定"做什么单 / 有没有价值"）
| 角色 | 职责 | 载体（module / class） |
|------|------|----------------------|
| 架构·找需求 | 闲鱼/网站/工作群找单、整理商机、可接性初筛 | roles/company.py · DemandFinderRole |
| 架构·价值确认 | 价值评级、找市场空白、给方向建议 | roles/company.py · ValueVerifierRole |
| 架构·竞品分析 | 竞品优劣势、差异化定位 | roles/company.py · CompetitorRole |
| 架构·销售 | 谈单、报价、跟进成单 | roles/market.py · SalesRole |
| 架构·客服 | 售前/售后/工单 | roles/market.py · SupportRole |

### 交付流水线（原有，不变）
产品 / 总师 / 经理 / 小组长 / 开发 / 评审 / 对齐 / 测试 / 找工具

### 能力底座线 · 持续开发（更快更稳成本更低）
| 角色 | 职责 | 载体（module / class） |
|------|------|----------------------|
| 架构·工具开发 | 自研沉淀复用工具、系统迭代、工具库管理（**区别于找现成工具**） | roles/company.py · ToolBuilderRole |

## 四、调度链路（经理=分工核心）

```
架构·总师(架构设计) ──[架构方案]──▶ 架构·经理(分工调度) ──[分工卡]──▶ 架构·小组长(单项目执行) ──▶ 交付流水线
```

- **架构·总师**：定"做什么、为什么、边界、模块、风险、版本"。
- **架构·经理**：消费架构方案，产出**任务分工卡**（谁负责哪个模块、依赖顺序、排期、验收归属）→ 派给小组长。**这是"根据架构分工"的落地节点。**
- **架构·小组长**：把分工卡拆成子任务，协调推进交付线。

## 五、接力规则（三战线贯通）

1. **任务书 + 接力卡**：每条线交接必带接力卡（任务书/输入上下文/当前进度/下一步/接手角色/输出契约）。
2. **三层触发**：新角色补 `[触发:架构·XX]` 显式标记 + 语义映射 + rules 兜底。
3. **回转（打回）**：下游不达标 `[回转] 退回:XX / 原因 / 下一步要求`，最多 3 次，超次标 blocked。
4. **打断（续跑）**：中断留 `当前进度` 续跑点，凭进度无缝接续。
5. **跨战线转交**：市场获客线成单 → 交给经理进交付线；交付线沉淀 → 交给工具开发进底座线。转交都走接力卡。

## 六、风险与规避（架构八步第 3 步结论）

| 级别 | 风险 | 规避 |
|------|------|------|
| 🔴 HIGH | 外部数据源（找需求/竞品）抓取不可控、易失效 | 情报线先做**模板化 + 人工投喂**，外部自动化后置为增强项 |
| 🟠 MEDIUM | 角色 8→17，语义触发可能混淆 | 每个新角色显式补 `[触发:架构·XX]` + 语义原型登记 |
| 🟠 MEDIUM | 经理/小组长边界若不清会重复 | 经理=全局分工调度（消费架构方案），小组长=单项目子任务拆解 |
| 🟡 LOW | 一次性全上工作量与调试成本高 | **三战线渐进**（市场获客→服务竞争→能力底座），每线验证后再推下一条 |
