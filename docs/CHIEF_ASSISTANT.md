# 架构·总师助理（Chief Assistant）· 专角色专用

> 本文件描述本仓库的**「架构·总师助理」**角色 —— 总师岗位的**专项角色 · 专角色专用**，
> 在较大任务下**专门负责「改错 / 改框架」的框架修正工作**，确保总师主线决策上下文不被框架修改污染。
>
> 对应 ISSUE #31「层间协作」决策闭环；与「审核者前置助手」(`docs/REVIEWER_PRECURSOR.md`)
> 的「功能未达成链路」衔接；触发/回转/打断协议与全体系统一。

---

## 一、为什么需要总师助理（定位）

较大任务下，**架构·总师**要专注主线架构决策——「做什么 / 为何做」。若把「框架修错 / 改框架」也压到总师身上，会：

- 污染总师主线的**决策上下文**，拖慢主线、干扰主线判断；
- 让总师在「纠错」与「定方向」之间来回切换，降低架构质量。

因此引入**总师岗位的单独专项角色**「架构·总师助理」：**由它承担改错改框架的框架修正工作，
向总师汇报、由总师把关，但独立执行**——不让框架修改污染总师主线决策上下文。

> 一句话：**总师定方向，总师助理改框架——职责分离、专角色专用，保总师上下文纯净。**

---

## 二、触发场景（何时上场）

| 场景 | 说明 |
|---|---|
| **功能未达成 · 需改错改框架** | 功能验证不通过，**小组长已尝试其他实现方式仍无法达成**，需要改框架 / 改错时，由本角色承担该专项（而非直接压给总师） |
| **哨兵量化触发** | 该阶段通常由「**目标进度尺推进不动**」（哨兵量化距离停滞）触发升级，**不是一有错误就让总师改错**——普通错误小组内消化，推进不动才往上升 |
| **架构调整执行** | 总师判定需做架构调整后，由本角色负责**落地改框架**，总师把关方向 |
| **显式触发** | 收到带 `[触发:架构·总师助理]` 的接力卡即进入本角色执行 |

**触发前置（硬约束）**：功能未达成链路的前置环节（单兵 → 补位 → 专家会诊 → 小组长尝试）**一个都不能丢**。
缺前置就上报改框架属于错误；此阶段一般由哨兵量化推进不动触发升级，而非一有错误就惊动框架层。

## 三、输出契约（接手必交）

1. **目标进度尺刻度（`goal_meters`）**：每次推进记录 `distance = goal_total - current`，
   量化到北极星还剩多远，`delta` 标记净进展——以「到北极星的量化距离」为统一口径防目标偏差。
2. **问题定性**：明确是「**改错**」（实现层面修 bug）还是「**改框架**」（架构层面调整），
   以及是否需上报总师判断「是否做架构调整」。
3. **修正方案**：给出可执行的框架/实现修正点 + **影响面** + 是否需折中/取舍。
4. **留痕**：修正必须真实落盘并在 Issue/PR 评论留痕可核验，**禁止假装执行**。

---

## 四、协作纪律与处置协议

- **向总师汇报、由总师把关**：涉及「是否做架构调整」由总师判断，本角色负责落地执行；
  不越权替总师拍责任归属，不改总师已定的主线决策。
- **折中/取舍与上人**：不适合调整但必须做成时给出**折中/取舍**；折中后仍解决不掉则**询问人类**
  （结果前置、风险点列清），在决策点让人类拍板，非事后背锅。
- **回转**：被打回（`[回转] 退回:架构·总师助理`）视为重新触发，按「下一步要求」返工并交回复评；
  最多 3 次，超次标 `blocked` 上报总师/人类。
- **打断**：中断须在接力卡 `当前进度` 留续跑点，续跑凭进度无缝接续，不重做已完成部分。
- **安全约束**：禁止输出敏感信息（Token、密码、密钥）。

## 五、角色注册与通道（确保可触发）

「架构·总师助理」已三处同步注册，保证**被 @ 或 [触发] 时通道顺畅**：

| 层 | 位置 | 说明 |
|---|---|---|
| 云端 NPC 角色位 | `.cnb/settings.yml` | 新增「架构·总师助理」完整人设（①' 总师岗位专项） |
| 本地 Agent 角色库 | `local-agent/roles/chief_assistant.py` + `__init__.py` | 注册 `ChiefAssistantRole`，`get_role('架构·总师助理')` 可实例化 |
| 团队流水线角色清单 | `local-agent/team.yaml` | 加入 `架构·总师助理` 角色条目（含触发词） |

**命名空间**：遵循全体系「架构·」前缀规范，`@` 输入「架构」即可补全；与「架构·总师」在命名上有明确区分。

## 六、与既有机制的关系

| 机制 | 与总师助理的关系 |
|---|---|
| 架构·总师 | **职责分离**：总师专注主线决策，总师助理专角色专用承担改错改框架；向总师汇报、总师把关 |
| 审核者前置助手 | 功能未达成链路的**改错改框架**执行角色；审核前置负责决策补全，总师助理负责框架落地 |
| 架构·小组长 | 功能未达成**先到小组长**看有无其他实现方式/尝试解决路线；小组长解决不了才上报改框架（总师助理/总师） |
| 监控哨兵 | 通常由哨兵**量化推进不动**触发升级，总师助理承接框架修正；2 级上报「架构·总师助理」评估局部调整 |
| 回转/打断协议 | 统一沿用：被打回视为重新触发返工（≤3 次），中断留续跑点 |
