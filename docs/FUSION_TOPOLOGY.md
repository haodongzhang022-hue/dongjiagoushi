# 融合拓扑规则引擎（Fusion Topology Router · 按任务规模选择）

> 本文档是 Issue #41「装一个规则机制，根据任务规模选择拓扑 + 融合机制」的架构产物留痕。
> 执行角色：架构·总师

---

## 背景 · 用户诉求

> "装一个规则机制，根据任务规模选择，而且不是选一个了，现在构建了融合机制，
> 是可以用新框架的处理规模不很大的情况的，只有规则变大到默认的框架不够
> 或者下面就是适合这种散沙类型高并发的，就触发这个。……就已经可以承载98%以上的任务了吧，
> 只有规模再大的时候走完上面再到这一步。……这种架构是确定有提速的，只是当前任务太小，
> 越大越明显，甚至用分形的方式，速度无论如何都是优势，只是需要针对这些情况有
> 缓存命中率的方案和分工方案，信息回传和合并的方案而已。"

核心三点：
1. **按任务规模选择拓扑**，而非"选一个"——是**融合机制**（多种拓扑按规模协同，不是非此即彼）；
2. **触发门控**：默认框架（公司式分工 dag）承载 ~98% 任务；只有**规模超默认承载** 或 **散沙型高并发** 才触发融合/散沙；
3. **大规模配套方案**：缓存命中率方案 + 分工方案 + 信息回传 + 合并方案。

---

## 分层选择（tier routing）

| 规模档位 | 判定 | 选用拓扑 | 说明 |
|----------|------|----------|------|
| **small** | 复杂度≤3 且 子任务≤5 | `scatter` 轻量一窝蜂 | 小/零散任务，不做重分工（防过度设计） |
| **medium** | 复杂度≤6 且 子任务≤20 | `dag` 公司式分工 | 承载常规任务 |
| **large** | 复杂度>6 或 子任务>20 | `dag` 公司式分工 | 仍属默认框架承载范围（~98%） |
| **huge** | 复杂度≥9 或 子任务>50 | `prefix`/`hybrid` 融合 | **规模超默认框架承载** → 触发融合 |

## 融合触发门控（不是必选）

| 触发信号 | 条件 | 动作 |
|----------|------|------|
| `scale_exceeded` | 档位 > large（即 huge） | 触发融合拓扑（prefix 水龙头蔓延 / hybrid 中央调控+瓜分） |
| `scattered_high_concurrency` | 零散 或（子任务>5 且 并发>10） | 直接用新框架一窝蜂（scatter） |
| 默认 | 中/大规模非散沙 | 走公司式分工（dag），不轻易上融合 |

**优先级**：`scale_exceeded` > `scattered` > `small` > 默认 dag。
即：规模超载的**架构化大任务**触发融合（prefix/hybrid）；**散沙型高并发**直接用新框架；小任务轻量；其余默认 dag。

## 四套配套方案（面向大规模/融合场景）

| 方案 | 落地要点 |
|------|----------|
| **① 缓存命中** | 共享前缀聚合为集群（缓存命中为索引）：同一 role 节点共享前缀只构造一次，后续节点命中缓存只付增量差异 token（水龙头蔓延）；不同集群天然并行 |
| **② 分工** | 超大规模：中央调控先吃核心/高价值（内部消化），余量子任务一窝蜂瓜分补全；或分形拆小组并行 |
| **③ 信息回传** | 抢单/水龙头节点各自完成即回传，gid 稳定寻址回传对象，统一收口到评审/测试节点 |
| **④ 合并** | 分形/抢单结果按最小模块粒度统一向上整合交付（commits 以小组为单位），避免多 agent 改同一对象冲突 |

## 用法

```bash
# 一条 API：规模评估 + 规则选择 + 四套方案
python3 -c "import sys;sys.path.insert(0,'local-agent');from topology import fusion;print(fusion.route(complexity=9,subtasks=60,concurrency=5)['selected'])"

# CLI 路由（超大规模 → 融合）
python3 local-agent/topology/fusion.py --route --complexity 9 --subtasks 60 --concurrency 5

# CLI 二级信息快照（人类俯瞰）
python3 local-agent/topology/fusion.py --overview

# 信号灯测试
bash local-agent/tests/test_topology_fusion.sh
```
